## Index Maintenance

### Monitoring Index Health (Quarterly)

```sql
-- Check for unused indexes (bloat)
SELECT schemaname, tablename, indexname, idx_scan
FROM pg_stat_user_indexes
WHERE idx_scan = 0
ORDER BY idx_blks_read DESC;
-- Expected: All critical indexes should have idx_scan > 0

-- Check index size
SELECT 
  schemaname, tablename, indexname,
  pg_size_pretty(pg_relation_size(indexrelid)) AS size
FROM pg_stat_user_indexes
ORDER BY pg_relation_size(indexrelid) DESC;
-- Expected: Largest indexes should be on high-volume tables (daily_records)

-- Reindex if fragmented (PostgreSQL)
REINDEX INDEX index_name;
-- Run quarterly if idx_scan is high but performance degrades
```

### Adding New Indexes

If a new slow query is detected:

1. Identify the WHERE clause columns
2. Create migration: `2026_MM_DD_000000_add_index_<table>_<columns>.php`
3. Use `Schema::hasIndex()` check (idempotency)
4. Test with EXPLAIN ANALYZE before committing
5. Monitor production for 1 week

Example migration:
```php
Schema::table('daily_records', function (Blueprint $table) {
    if (!Schema::hasIndex('daily_records', 'daily_records_new_index')) {
        $table->index(['column1', 'column2']);
    }
});
```
